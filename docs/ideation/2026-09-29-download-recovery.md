# 2026-09-29 下载任务恢复迭代

## 分析与目标

上一轮补齐了命令交互和退出码，但文件复用仍要求用户重新输入漫画 URL 和范围。
程序重启后缺少“上次下载什么、哪些失败、如何继续”的入口。本轮将下载计划保存下来，
并增加可直接操作的任务列表、详情和恢复命令。

检查恢复链路时发现两个与恢复结果相关的问题：旧实现直接写最终 ZIP，打包失败或中断
后残留文件可能被误判为已完成；打包只比较目录条目数，额外文件可能掩盖缺失图片。
本轮同步修复，避免恢复任务报告虚假的成功。

## 用户可见行为

- `d` / `v` 与对应直接子命令在得到章节计划后创建任务，显示可复制的 12 位 ID 前缀。
- `tasks` 列出当前保存目录的历史任务，`tasks <ID>` 查看每话结果和错误。
- `retry <ID>` 继续失败、部分失败及未开始的章节，支持重启后恢复。
- 保留原始章节选择，不再次抓取漫画详情；每话处理结束后保存一次记录。
- 已成功与已跳过章节保持不变；恢复汇总显示整个任务的累计结果。
- 支持当前运行配置和覆盖选项；覆盖只影响此次恢复的未完成章节。
- 驱动初始化失败时保留待下载计划；缺失源、损坏记录、占用任务均提供错误说明。
- 任务列表与详情在 40、80、120 列终端下可查看。

## 实现约定

- `download/jobs.py` 负责计划模型和执行；调用源已有的范围下载流水线。
- `ComicSource.download_vols(..., on_result=...)` 在逐话结果产生后回调，保存失败立即停止，
  避免继续下载大量无法记录的章节；原有不带回调的调用保持兼容。
- `download/job_store.py` 使用版本 1 的 JSON 文件，位于输出目录的
  `.comic_downloader/jobs/<完整ID>.json`；数据校验后写临时文件，flush/fsync 后原子替换。
- 同一任务通过系统文件锁互斥，Windows 使用 msvcrt，其他平台使用 fcntl。
  锁文件存在不等同于任务仍在执行；进程终止后系统释放锁，无需删除“陈旧锁”。
- 任务被强制终止后可能保留 running 状态，界面显示“未结束”；恢复命令重新取得锁并读取记录。
- ZIP 通过临时文件写入并原子替换；复用前检查可读性、非空和 CRC。
  打包仅写入 `0001.jpg` 等本次预期文件，保留目录中的其他文件。
- 修正 DownloadProgress 协议的返回类型，使真实下载流水线的类型检查能够通过。

## 验证与边界

验证包含正常任务、多分组范围、部分失败、KeyboardInterrupt、保存失败、无可用驱动、
损坏 JSON、模糊 ID、跨进程锁竞争和进程崩溃后的锁释放。另使用本地 HTTP 服务测试完整
图片下载、失败恢复、打包和持久化链路：恢复时仅请求此前失败的图片，并保持成功卷的 ZIP 不变。

归档测试覆盖截断 ZIP、空 ZIP、零字节成员、CRC 损坏、写入/替换失败、临时文件清理，
以及额外文件不能代替预期图片。Windows 上运行全部测试与实际 CLI 进程冒烟检查。

最终验证结果：

- 全量测试 213 项通过，较本轮开始时新增 43 项。
- 任务执行、任务存储、归档三个模块合计语句覆盖率为 91%。
- 本轮 13 个 Python 文件通过 Ruff 检查和格式检查；8 个生产代码文件通过 Pyright。
- 6 个真实 CLI 进程场景通过：任务列表、详情、已完成重试、源不可用、任务不存在、缺少参数。
- 实际检查 40/80/120 列输出；窄屏任务列表合并状态和数量，任务 ID 不折行。
- 子进程在记录第一话后强制退出，后续执行只继续剩余两话；验证了真实进程退出后的记录和锁恢复。

本轮不包含后台队列调度，也不重新验证已完成任务的输出文件。手动删除完成文件后应创建
新任务；图片内容解码校验、跨平台运行实测和线上漫画站点验证仍是后续工作。
