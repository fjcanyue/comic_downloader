# 2026-09-29 搜索诊断与长列表导航

## 代码分析与范围

前两轮改善了命令边界和下载恢复，但搜索仍有三个可直接影响操作的问题：
进度在全部任务结束后才更新；适配器吞掉网络或解析异常后，界面将失败当作空结果；
每个源只保留前 10 条，章节列表则一次性输出全部内容。

本轮围绕搜索到章节选择的流程迭代，以本地代码、离线 HTML 样例和本地 HTTP 服务验证。

| 维度 | 实现 | 用户可见行为 |
| --- | --- | --- |
| UI/UE | 逐任务完成回调、逐源状态表 | 等待慢源时可看到其他源已完成，报告包含耗时与错误 |
| 可操作性 | `p [页码]`、`ch <分组> [页码]` | 搜索每页 20 条，章节每页 60 话，保持原序号 |
| 功能完整性 | 搜索诊断包装、页面与 XPath 错误记录 | 区分未检出、失败、部分结果和已跳过 |
| 数据保留 | 移除交互搜索的每源 10 条限制 | 保留各源本次返回的全部条目 |
| 可恢复性 | 保留已解析条目、状态报告可回看 | 部分解析失败仍可选择有效条目，`status` 重显报告 |
| 资源管理 | 搜索浏览器在工作线程内创建、使用与关闭 | HTTP 搜索不等待慢浏览器初始化，避免跨线程复用浏览器 |

## 实现约定

原有源的 `search()` 仍返回列表；`search_with_diagnostics()` 将可见错误和条目一起返回。
一次新搜索重置诊断，避免旧失败污染下一次结果。HTTP 页面加载失败优先保留状态码和原因。
搜索使用独立浏览器会话并在结束后关闭；详情和下载继续使用主线程中的缓存浏览器。
手写适配器补充网络和条目解析诊断；已知搜索需要验证码的漫画站明确跳过并提示 URL 操作。
关键词中的空格、中文、`&`、`/`、`#` 在 URL 拼接时编码。

完成进度按任务实际结束更新，最终报告和结果序号按配置源顺序排列。
至少一个源完整执行成功时 CLI 返回 0（包括未检出）；全部失败、跳过，或只有部分结果时
返回 1。有效的部分结果仍会展示。

交互翻页只读取缓存，不请求网络。`p 2` 之后仍可用 `i 21` 选择原来的第 21 条；
`ch 1 2` 展示原第 61～120 话，可直接 `v 1 61 65` 下载第 61～65 话。
直接 CLI 的 `search` / `info` 输出完整列表，因为该模式没有后续交互会话。
40 列终端的源报告将错误说明放在表格下方，避免说明挤压状态列。

## 边界与后续方向

“未检出”仅表示本次没有解析出条目，不能证明站点健康。页面结构判断依赖各源现有选择器，
需要继续积累脱敏网页样本。这一轮未实测外部站点与真实浏览器下载链路。
分页不代表自动获取网站后续搜索页，也没有加入结果过滤或后台下载队列。
后续可独立推进图片解码校验、站点解析样本回归，以及带独立状态的下载排队。
