# 章节目录解析迭代与验证

本轮基于 `e983880` 开发，测试基线为 363 项。前两轮已改善搜索和任务长列表浏览，
本轮将重点转向目录正确性：下载计划依赖详情解析，如果章节在解析阶段丢失，
后续任务全部成功也不能证明网站目录完整。

## 代码分析与改动

| 问题 | 改动与结果 |
| --- | --- |
| 读漫屋、漫画柜拼接源域名与章节地址 | 共享 HTTP 地址解析，支持文档相对路径、完整地址与协议相对地址，排除空链接、纯锚点和非 HTTP 地址 |
| 直接读取节点 `.text` 丢失嵌套标签文字 | 共享完整节点文本提取，漫画站名称 XPath 使用 `string(.)` |
| 31 漫画分组 XPath 子串匹配也选中 `zj_list_head` 和 `zj_list_con` | 按完整 CSS 类名匹配 `zj_list`，避免伪分组 |
| 缺失字段或追加接口异常只写日志 | 将解析提示带到详情和下载入口，保留其余有效章节；共用分组解析器为缺失标题生成名称 |
| 同一分组重复章节进入下载计划 | 在目录收尾阶段按规范化地址去重，保持现有顺序，跨分组保留 |
| 读漫屋“加载更多”使用全局 XPath | 限定在当前分组内部或紧邻的追加入口，避免其他分组重复请求 |
| 追加请求资源与等待边界不完整 | 读漫屋追加接口与 GoDa API 在成功和失败路径关闭响应；GoDa API 增加 30 秒请求超时 |
| API 单条异常影响有效章节 | 对列表与条目字段分别校验，异常条目产生提示，后续有效条目继续解析 |

共享逻辑位于 `downloader/sources/parsing.py`。去重按每个分组独立维护集合，
章节扫描为线性过程；没有增加站点请求。读漫屋多分组回归确认只有带追加入口的分组
发送 POST，没有将离线请求次数改善当作真实网络速度提升。

## 用户可见行为

详情新增“章节解析提示”面板，最多展示 5 项，更多提示指向日志。提示通过 Rich `Text`
输出，外部字符串不会被当作标记解析。在 40、80、120 列终端验证换行及文字可读性。

创建下载计划前会重显提示，并说明计划只覆盖已解析的所选章节。部分目录仍允许下载；
成功退出码继续表示当前命令或任务的执行结果，不把目录提示改成下载失败。
没有可下载章节时沿用原有拒绝创建空任务的行为。

提示只保存在本次详情对象中，不修改历史任务 JSON。用户需要重新获取详情才能发现
新增或之前漏掉的章节，`retry` 继续恢复已有计划。示例见 `docs/catalog-notes.svg`，
该文件由真实 Rich 渲染生成，内容为演示数据。

## 回归样本与验证范围

`tests/fixtures/sources/` 为 7 个默认启用源各提供一份详情 HTML，并包含 GoDa 详情 API、
读漫屋追加 API 和无法识别的结构样本。这些是依据现有配置和适配器编写的合成契约样本，
不是线上抓取快照，不证明网站当前结构、连通性或图片下载可用。
样本不含真实漫画图片、用户 Cookie 或令牌；来源约束记录在该目录的 README 中。

49 项目录测试覆盖所有默认源、嵌套标题、顺序、相对及完整地址、坏链接、空目录、
结构变化、缺失分组标题、API 异常条目、响应关闭、超时参数、分组局部追加、
组内去重与跨组保留。另外新增 3 项终端宽度测试，以及 1 项从详情到下载入口的工作流测试。

验证结果：

- 全量测试：`pytest -o addopts= -q`，416 项通过。
- Ruff：本轮修改的 11 个 Python 文件检查及格式检查通过。
- Pyright：`main.py downloader tests`，0 错误、0 警告。
- Rich 输出：40、80、120 列均可读取提示与章节列表，80 列输出保存为 README 插图。

本轮未访问实际漫画源，也未运行浏览器或真实图片下载验证。新增回归验证代码对既定
结构和异常输入的处理能力，真实站点结构仍需要另外采集与验证。
