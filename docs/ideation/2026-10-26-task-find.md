# 任务查找、界面层级与错误摘要缓存

本轮以 `769e22b` 为基线，原有 454 项测试通过。项目是 Python / Rich 终端应用，
已具备搜索筛选、任务分页、跨进程恢复和归档功能。本轮沿用现有架构与配色，
集中改进历史任务的定位和浏览，不增加依赖或变更任务文件格式。

## 代码审查与选择依据

- `TaskQuery` 和 `matching_jobs` 原先只支持状态过滤。历史计划增加后，寻找某本漫画
  需要连续翻页，或者先知道任务 ID。新增按漫画名、源代码和 ID 的本地查找。
- 任务表只显示 ID、漫画、完成数和状态，跨源同名漫画难以区分。增加来源显示；
  宽终端增加更新时间，窄终端将来源折叠到漫画名下方。
- 列表缺少全局状态概览。增加各状态的有效计划数量，并把损坏记录单独计数；
  下方查询面板明确展示状态、关键词、匹配数和页码，避免混淆全部记录与当前结果。
- `JobStore.list_summaries` 已缓存有效记录，但损坏 JSON 每次浏览仍重新读取、解码并
  抛出异常。增加同样受文件签名约束的错误摘要缓存，保留每次错误提示。

## 操作与视觉设计

语法为 `tasks [状态] [页码] find <关键词>`；分页和任务详情的旧语法继续支持。
明确指定列表页码时先写状态，例如 `tasks all 2 find 猎人`，避免与纯数字任务 ID 混淆。
`find` 后所有词作为关键词，忽略大小写、全部匹配，允许不同词命中不同字段。
关键词按字面显示，不作为 Rich markup。查找只针对未归档计划的元数据，不扫描章节。

交互模式的 `tasks next/prev` 保留状态与关键词；新的查询默认回到第一页，明确指定
页码时使用该页。无结果时保留查询并提示返回全部任务，越界或参数错误不覆盖已有浏览状态。
直接 CLI 输出带状态、页码和关键词的导航命令。`tasks` 清空条件并回到全部计划首页。
查找不改变当前漫画、下载源、计划内容或重试范围，界面明确提示 `retry all` 不受查找约束。

视觉采用原有 cyan 强调色，以绿色、红色、黄色分别表达完成、失败和中断状态，并保留文字
标签供无色终端阅读。任务 ID 强调、来源和更新时间弱化。少于 60 列时合并状态与完成数；
60～99 列保持四列表格；100 列起增加独立来源列和 UTC 更新时间。40、80、120 列均检查
实际 Rich 文本渲染，测试使用终端字符宽度检查溢出。预览环境显式排除 `TERM=dumb` 对
强制彩色 Console 宽度的干扰，并断言实际宽度；演示图由实际输出导出，不代表真实下载数据。

## 缓存边界和性能证据

错误缓存只保存文件签名与错误字符串，不保留异常对象、堆栈、章节列表或 JSON 内容。
签名沿用纳秒修改时间、创建/变更时间、大小和 inode。解码前后签名一致才保存错误，
变更后重新读取、删除后清除；临时 I/O 错误不缓存。详情和重试仍读取原始记录。
归档列表共用 `JobStore`，同样受益。缓存是进程内优化，不生成额外索引。

本地临时目录准备 150 个有效计划（每个 100 话）和 20 个损坏 JSON，包装 `_read`
统计调用次数。先冷读，再连续读取 10 次；对照组每轮清空错误缓存，但保留原本就有的
有效摘要缓存，从而只比较本轮新增的优化。一次测量结果：

| 场景 | JSON 读取/解码次数 | 本次耗时 |
| --- | ---: | ---: |
| 冷读 170 条记录 | 170 | 7.5289 秒 |
| 保留两种缓存，连续浏览 10 次 | 0 | 0.8506 秒 |
| 只保留有效摘要缓存，连续浏览 10 次 | 200 | 0.9623 秒 |

时间受 Windows 文件系统、缓存和机器负载影响，不能作为固定速度保证；稳定收益是避免
反复读取未变化的损坏记录。有效摘要的热缓存是已有能力，本轮未把该收益计作新增优化。
每次仍扫描文件元数据，首次加载成本不变，也不影响图片网络下载速度。

## 验证结果

- 全量回归：475 项通过，较基线新增 21 项。
- 改动的 9 个 Python 文件通过 Ruff 检查和格式检查；项目 Pyright 为 0 错误、0 警告。
- 新回归覆盖多词跨字段查找、大小写、字面 markup、非法参数、连续翻页和越界状态保留、
  当前漫画与计划内容保留、直接命令预校验、三个终端宽度及来源/时间展示。
- 缓存回归覆盖重复损坏读取、外部修复、删除、临时 I/O 失败，以及解码期间发生修复的竞争情况。
- 用真实 `main.py` 子进程验证带关键词的第二页、明确的下一页命令，以及有损坏记录返回 1、
  移除临时损坏记录后返回 0。全部使用本地合成计划，没有访问漫画网站或改动真实下载记录。

复核命令：

```shell
uv run pytest -o addopts= -p no:cacheprovider -q
uv run pyright --pythonpath .venv/Scripts/python.exe
```

本机验证直接使用项目 `.venv/Scripts/` 下的工具，未升级依赖。

## 后续优先级

1. 归档查找及批量操作候选预览：复用查找语义，并明确恢复入口与操作范围，再考虑清理。
2. 源解析回归：补充带采集日期、来源说明的真实脱敏搜索与图片页快照，避免将合成测试通过
   误认为站点当前在线可用。
3. 首次历史扫描性能：针对大量真实计划测量 JSON 解码和文件系统成本后，再决定是否增加
   持久化索引；必须覆盖跨进程更新、损坏与修复，不以陈旧缓存换取更快显示。
4. 网站搜索后续分页：按源实现协议、去重及限速，保留会话中稳定的选择序号。
