# 归档查找、连续浏览与查询反馈

本轮基于 `fcfa024` 分析并迭代，基线全量测试为 475 项。项目是 Python / Rich 终端应用，
已经具备多源搜索、目录提示、下载完整性检查、计划恢复、任务查找与单计划归档。

## 代码分析与迭代选择

| 方面 | 当前代码证据 | 本轮决策 |
| --- | --- | --- |
| UI/UE | `TerminalPresenter` 的任务浏览有条件面板，归档只有总数和页码；空列表始终提示“暂无归档” | 为归档增加条件、匹配数、全部可读记录数和损坏计数；区分无记录、无匹配、全部不可读 |
| 操作性 | `TaskQuery` 已支持查找与连续翻页，`ArchiveQuery` 只接受明确页码 | 统一两种列表的查找语义；归档列表与章节详情都支持 next/prev |
| 功能完整性 | 已完成计划移入归档后，无法使用 `tasks find` 定位 | 增加 `archive find`，覆盖查找、查看详情、按 ID 恢复的完整流程 |
| 一致性 | Shell 与 CLI 共用解析器，但 CLI 没有跨命令会话 | 相对翻页仅用于交互模式；CLI 提供包含关键词的明确翻页命令 |
| 可维护性 | `matching_jobs` 已支持跨字段多词匹配，`JobStore.archive_view()` 已复用摘要缓存 | 直接复用匹配、缓存和存储机制，不新增依赖、索引或任务格式 |

本轮优先解决现有历史管理流程中的不一致。网络搜索分页需要逐源协议适配及限速设计，
真实网页回归需要带采集日期的脱敏样本；它们作为独立后续迭代，不以本地测试代替在线验证。

## 操作与状态

```text
archive find 猎人 morui
archive next
archive prev
archive list 2 find 猎人 morui
archive show a1b2c3d4
archive next
archive restore a1b2c3d4
archive
```

示例 ID 需要替换为实际 ID。查找按空白分词、忽略大小写，所有词必须在漫画名、源代码或 ID
中匹配，允许跨字段命中。`find` 后所有文字作为字面关键词，不搜索章节内容。明确页码使用
`list <页码>`，纯数字十六进制前缀仍按任务 ID 处理。

`Shell.archive_query` 独立于任务、搜索和漫画选择状态。新查询默认第一页，`archive` 或
`archive list` 清除关键词。参数错误、越界或详情读取失败保留之前的查询；有效列表中有
损坏记录时，仍展示其余数据并记住该查询，同时报告错误并返回失败状态。

归档与恢复操作不覆盖浏览状态，也不会因关键词自动扩大或缩小操作范围。打开详情后，
保存完整 ID，连续翻页改为浏览该计划章节；返回查找列表需重新输入查找命令。
短 ID 的冲突检查涵盖全部可读归档，不局限于当前匹配结果。

每次浏览重新读取文件元数据并复用已有摘要缓存。其他进程恢复计划后，列表页数可能缩减；
越界时保留查询并提示可用页码，用户可返回前页或重新查询。归档记录、漫画文件和下载行为
沿用既有实现，不因为浏览而重写记录或发起网络请求。

## 界面

查询面板采用原有 cyan 强调色，条件与结果分行呈现，作用范围明确标为“当前保存路径 ·
仅含归档计划”。损坏记录独立标记为黄色，不计入可读记录总数。无匹配时引导输入 `archive`
清除条件；只有损坏记录时提示检查记录错误，避免误报没有归档。

表格复用现有响应式布局：窄终端将源代码放在漫画名下方，宽终端保留独立来源和更新时间。
查找文字使用 Rich `Text`，`[red]` 等输入不会被当作样式解释。导航随运行模式变化：交互模式
提供 `archive next/prev`，直接 CLI 提供 `archive list 2 find <关键词>`。

![归档查找演示](../archive-find.svg)

预览使用合成数据，仅展示 3 条样例行，查询总数用于演示分页，不代表真实下载记录。
可运行 `python docs/render_archive_find.py` 重新生成 SVG 并查看相应终端文本。

## 验证范围

- 解析器：旧语法兼容、大小写、多词、关键词包含命令词、空关键词、非法参数、纯数字 ID、
  列表与详情连续翻页，拒绝把归档/恢复动作当作可翻页查询。
- Shell：查找及 ID 命中、边界状态保留、独立任务查询状态、当前漫画和来源保持、记录字节
  不变、筛选外 ID 冲突、明确单 ID 恢复、外部恢复后的缓存刷新与页数缩减。
- CLI：真实 `main.py` 子进程执行归档、按名称/来源/ID 查找、无匹配、详情和恢复；解析器
  在 Shell 创建前拒绝错误语法及 next/prev。直接输出的分页命令保留页码与关键词。
- UI：40、80、120 列下检查字面关键词、匹配数、页码、损坏记录计数和两种导航模式；
  使用终端字符宽度验证换行不溢出，检查实际 Rich 文本预览。
- 错误处理：损坏记录不隐藏有效计划，全部不可读不再显示“暂无归档”；损坏记录使执行返回 1，
  正常无匹配仍视为成功。

测试全部使用合成数据和临时目录，不访问漫画站点，也不移动真实下载记录。

验证结果：全量 **503 项通过**，较基线新增 28 项；8 个改动 Python 文件通过 Ruff 检查和
格式检查；项目 Pyright 为 **0 错误、0 警告**；`git diff --check` 无空白错误。
本机使用已有 `.venv/Scripts/` 工具，未升级依赖，复核命令为：

## 后续开发优先级

1. **批量归档候选预览与执行复核**：以已完成计划为候选，展示数量及范围；执行时重新校验
   状态并沿用每计划锁，逐项报告成功和失败，提供恢复路径，再讨论保留期与清理。
2. **搜索及图片解析回归扩展**：积累带来源、采集日期和脱敏说明的真实页面，覆盖结构变更、
   空结果和反爬页面；维持“离线解析通过”与“网站当前在线可用”的区别。
3. **网站后续搜索分页**：按源适配协议，增加显式加载入口、去重、限速及稳定序号；当前本地
   搜索结果翻页不会自动获取网站后续页面。
4. **大型历史库首次扫描**：先用实际规模测量文件扫描和 JSON 解码成本，再评估持久化索引；
   保证跨进程更新、损坏修复和删除可见，不以陈旧结果换取显示速度。
